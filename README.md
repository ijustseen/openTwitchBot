# OpenBot

Небольшое окно для macOS и Windows: бот сидит в чате Twitch на вашем компьютере и отвечает на команды вида `!hello`. Что делает команда, задаётся обычным Python-скриптом. Скрипт можно написать в окне или вставить целиком. Команду можно выключить, не удаляя её.

## Запуск

Нужен Python 3.11 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

При первом запуске рядом с программой появится `data/config.json`. Туда пишутся канал, токен и список команд. Сами скрипты лежат в `data/commands/`. Этот файл с токеном в git не попадает.

## Токен

Сайт twitchapps.com/tmi закрыт. Токен больше не берётся оттуда и не из чужого генератора: его выдаёт ваше приложение Twitch, а OpenBot забирает его через браузер.

1. Закройте окно, если оно уже открыто, и снова запустите `python main.py`.
2. Нажмите «Войти через Twitch».
3. В [консоли приложений](https://dev.twitch.tv/console/apps) зарегистрируйте приложение. В OAuth Redirect URL вставьте ровно `http://localhost:17563/callback`. Категория — Chat Bot.
4. Скопируйте Client ID. Нажмите New Secret и сразу скопируйте Client Secret: Twitch показывает его один раз.
5. Вставьте оба значения и нажмите «Открыть браузер и войти». В браузере войдите аккаунтом, от которого бот будет писать в чат, и разрешите чтение и отправку сообщений.
6. В поле «Канал» укажите канал, чей чат слушать, и нажмите «Старт».

Свой аккаунт канала подходит: ответы идут от вашего ника, модератора себе выдавать не нужно. Если входите отдельным аккаунтом бота, выдайте ему модератора на канале. Иначе при режиме «только для фолловеров», «только для подписчиков» или медленном режиме Twitch может не пропустить его сообщения, а одинаковые ответы вроде `pong` — скрывать.

После входа в шапке окна появится аккаунт, от которого бот пишет. Секрет и токен остаются в `data/config.json` на этом компьютере. Когда токен истечёт, программа обновит его сама, пока вы не отзовёте доступ в настройках Twitch.

## Команды

Новая команда открывается с таким шаблоном:

```python
# ctx.user, ctx.args, ctx.message, ctx.channel, ctx.is_mod
# ctx.reply("текст") — сообщение в чат
# print(...) — строка в лог программы

def run(ctx):
    ctx.reply(f"Привет, {ctx.user}!")
```

`run` — обычная функция, не `async`. Сообщение `!hello мир` попадёт в команду `!hello`, а `ctx.args` будет `["мир"]`. Регистр триггера не важен.

- Переключатель в списке выключает команду и оставляет её на месте.
- «Удалить» убирает команду и файл скрипта.
- «Проверить» гоняет текст из редактора на фиктивном пользователе `tester` и пишет ответ в лог. В чат ничего не уходит.
- Пока бот в сети, «Сохранить» начинает действовать сразу, без перезапуска.

Кулдаун считается на всю команду, а не на каждого зрителя. «Модераторы и стример» пускает модераторов канала и его владельца.

Скрипт запускается отдельным процессом Python с ограничением около 10 секунд, чтобы ошибка в команде не закрыла окно. Песочницы нет: скрипт может читать файлы, ходить в сеть и запускать программы от вашего имени.

В комплекте две команды: `!ping` отвечает `pong`, `!hello` здоровается.

Как устроены вход, поля `ctx`, проверка и сборка, собрано на одной странице: [docs/index.html](docs/index.html). В окне её открывает кнопка «Вики». Кнопка «Для нейросети» копирует инструкцию, с которой модель пишет команду под этот бот.

## Сборка окна

На macOS получается `OpenBot.app`, на Windows — папка с `OpenBot.exe`. Одну машину хватает только на свою систему: архив для второй собирает GitHub Actions. Для команд в собранной программе на компьютере всё равно должен быть установлен Python 3.11 или новее: скрипты запускаются им, а не упакованным окном.

Локально:

```bash
pip install -r requirements-build.txt
python scripts/build.py
```

Архив лежит в `dist/release/`. Папка `data` с настройками создаётся рядом с `.app` или `.exe`. Токен из вашего `data/config.json` в сборку не попадает.

Релиз на GitHub собирается сам после каждого коммита в `main`. Workflow лежит в `.github/workflows/release.yml`: он ставит зависимости, гоняет тесты и публикует zip для macOS (Apple Silicon) и Windows. Номер берётся из последнего релиза и увеличивается на одну цифру: после `v0.1.2` следующий коммит становится `v0.1.3`. Коммиты в других ветках релиз не создают.

Больший шаг по-прежнему ставится тегом, например `v0.2.0`. Следующие коммиты в `main` пойдут как `v0.2.1`.

```bash
git tag v0.2.0
git push origin v0.2.0
```

Сборки не проходят проверку Apple: на компьютере нет платного сертификата Developer ID, без него Gatekeeper это окно не убирает. Если macOS пишет, что не удалось подтвердить отсутствие вредоносного ПО, нажмите «Готово», откройте «Системные настройки» → «Конфиденциальность и безопасность» и внизу нажмите «Всё равно открыть» рядом с OpenBot. На Windows SmartScreen предупредит, что издатель неизвестен.

Номер версии в архиве — это номер релиза. Локальная сборка без него получает версию `0.0.0` и обновления не проверяет.

## Обновления

Собранное приложение при запуске смотрит последний релиз на GitHub. Если он новее, под шапкой окна появляется «Обновить». Кнопка скачивает zip для этой системы, закрывает окно и открывает его снова. Папка `data` с токеном и командами не заменяется.

Запуск через `python main.py` обновления не ставит. Уже выложенный релиз без этой функции сам обновиться не сможет: один раз новую сборку нужно скачать руками, дальше это делает кнопка.
